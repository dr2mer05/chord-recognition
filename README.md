# Chord Analysis Lab

음원의 코드 진행을 인식하고 로마숫자·화성 기능·대체 코드를 살펴보는 개인 학습용 웹앱입니다.
FastAPI, HTML/JavaScript, SQLite를 사용하며 기본 분석은 Linux CPU에서 실행합니다.

2026-11-14 사용자 결정으로 YouTube 음원 확보·Render 검증은 보류하고,
박자·코드 인식의 평가와 개선을 우선합니다. [현재 개발 상태와 기준선](docs/development-status.md)을 참고하세요.

## 실행

Python 3.12에서 검증한 CPU 의존성 조합을 제공합니다.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-cpu.lock
python -m chordapp serve
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. iPad에서는 본인만 접근할 수 있는
클라우드 개발 환경의 브라우저 미리보기를 사용하세요. 현재는 개인 단일 사용자용이며,
로그인·사용자별 데이터 격리는 없습니다. 공개 서비스로 배포하기 전에는 접근 제어가 필요합니다.

`requirements.txt`는 주요 의존성, `requirements-cpu.lock`은 검증 환경의 전체 고정 버전입니다.
beat_this·Demucs·외부 인식기는 기본 설치에 포함하지 않았습니다. 필요할 때
`requirements-models.txt`를 검토하고 설치하세요. 모델을 설치하면 사용하는 엔진과 비용·결과가 달라집니다.

## iPad에서 검색 설정하기

기본 검색 API는 서버에서 Google에 요청합니다. 개인 모드로 사이트를 연 뒤 **검색 설정**을 눌러
YouTube Data API 키를 입력하고 **연결 확인 · 저장**을 선택하세요. 연결을 확인한 키만 저장하며
서버 재시작 없이 검색창이 활성화됩니다. 저장한 키는 화면에 다시 표시하지 않습니다.
키는 저장소에서 제외한 서버의 `.env`에 소유자만 읽고 쓸 수 있는 권한으로 기록합니다.
다른 설정·주석은 보존하며, 연결 또는 저장 실패 시 기존 키를 유지합니다.

키 발급은 본인의 Google 계정으로 다음 순서로 한 번 진행합니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com)를 사용 설정합니다.
3. [사용자 인증 정보](https://console.cloud.google.com/apis/credentials)에서 **API 키**를 만듭니다. 공개 영상 검색에는 OAuth 동의 화면이 필요하지 않습니다.
4. API 제한사항을 **YouTube Data API v3**로 설정합니다. 서버에서 요청하므로 웹사이트 HTTP referrer 제한은 맞지 않습니다. Codespaces의 외부 IP는 고정되지 않을 수 있습니다.
5. 키를 채팅이나 코드에 보내지 말고, 사이트 설정란에 붙여넣습니다.

현재 공식 기본 검색 할당량은 하루 100회입니다. 콘솔의 실제 할당량이 기준이며 추가 할당량이나
유료 서비스는 자동 신청하지 않습니다. 같은 검색은 1시간 재사용하고, 검색 결과 메타데이터도
1시간 뒤 캐시에서 정리해 불필요한 요청을 줄입니다. 키 연결 확인은 검색 대신 `videos.list`를 사용합니다.
키가 잘못되었거나 API 미사용 설정·키 제한·할당량·네트워크 오류가 있으면 원인별 안내를 표시합니다.

**검색 설정 · 실행 상태**에서 실행 중인 앱 버전·검색 설정·개인 분석 도구·최근 오류를 볼 수 있습니다.
**상태 복사**로 진단 정보만 공유할 수 있으며 키는 포함하지 않습니다. 복사가 안 되는 기기에서는
이 화면의 스크린샷으로 상태를 전달할 수 있습니다. 서버 환경변수에 별도 키를 지정했다면 재시작 시
그 값이 `.env`보다 우선한다는 기존 규칙은 유지됩니다.

음원 연결 실패는 YouTube 자동화 확인·프록시·요청 빈도·영상 접근 권한·지역·TLS·JavaScript 처리·
형식·변환 실패로 구분합니다. 원문 오류·URL·키·사용자 경로는 공유하지 않고, 분류 코드와 처리 단계·
종료 코드·확인된 HTTP 상태만 표시합니다. 이 분류는 확인된 오류 문구에 근거하며 접근 제한을 해제하지 않습니다.
Deno·FFmpeg는 파일 존재뿐 아니라 실제 버전 명령 실행을 확인하고 EJS 설치 버전도 표시합니다.

- [공식 인증 안내](https://developers.google.com/youtube/data/guides/authentication)
- [공식 할당량 안내](https://developers.google.com/youtube/data/determine_quota_cost)

## YouTube 링크로 분석하기

개인 전용 자동 분석과 별도 음원 연결의 두 경로를 제공합니다. 별도 음원이 등록된 영상은
그 연결을 우선 사용합니다. 해제·만료된 연결은 자동 다운로드로 대체하지 않습니다.

### 개인 전용 자동 분석

개인 Codespaces에서는 시작 스크립트가 포트 8000을 **Private**로 설정한 다음 자동 분석을
활성화합니다. 기존 Codespace를 업데이트할 때는 다음을 실행하세요.

```bash
git pull --ff-only origin feat/authorized-audio-sources && bash scripts/start-dev.sh --restart
```

시작 스크립트가 변경된 의존성을 확인하고 설치한 뒤 서버를 재시작합니다. 첫 토큰 공급기 설치에는
몇 분이 걸릴 수 있습니다. **Codespaces를 다시 시작할 때** 자동 갱신하려면 현재
`.devcontainer` 설정이 적용되어 있어야 합니다. 기존 Codespace는 컨테이너 재빌드가 필요할 수 있습니다.
설정이 적용되면 현재 브랜치를
`git pull --ff-only`로 갱신합니다. 직접 수정했거나 미추적 파일이 있으면 자동 갱신을 건너뛰며,
원격 접속·병합에 실패해도 사용자 작업을 지우지 않고 현재 버전으로 시작합니다.
설치 목록이 바뀐 경우에만 의존성을 다시 설치합니다. 갱신 기록은 `work/auto-update.log`에 남습니다.
화면 새로고침만으로 실행 중인 서버가 업데이트되지는 않습니다.

사이트를 새로고침하고 영상 링크를 입력한 뒤 **분석**을 누릅니다. 검색은 별도로
`YOUTUBE_API_KEY`가 필요하지만 링크 입력에는 필요하지 않습니다.
이 경로는 `yt-dlp`와 FFmpeg·Deno·설치된 EJS 패키지를 사용하며 분석 엔진은 기존과 같습니다.
개인 Codespaces에서는 PO Token 공급기를 함께 실행합니다. 로컬 환경은
`requirements-private.txt`를 설치하고 `.env`에 다음 값을 설정한 뒤 서버를 재시작합니다.

```dotenv
CHORDAPP_PRIVATE_MODE=1
CHORDAPP_ENABLE_YTDLP=1
CHORDAPP_ENABLE_POT=1
```

두 설정이 모두 켜져야 동작합니다. 앱 자체에는 로그인이 없으므로 개인 모드는
비공개 포트 또는 본인만 접근 가능한 환경에서 사용하세요. 이 설정 자체가 접근 제어를 제공하지는 않습니다.
개인 이용만으로 다운로드 권한이나 YouTube 약관의 예외가 부여되는 것은 아닙니다.
향후 공개 서비스의 음원 공급 경로는 별도로 검토해야 합니다.

음원은 요청마다 독립적인 임시 폴더에 받아 **분석 성공·실패 후 삭제**하며 다운로드 API는 제공하지 않습니다.
정상 처리와 시간 초과 시 자식 FFmpeg 프로세스도 정리합니다. 서버 강제 종료나 머신 중단 시에는
잔여 임시 파일이 남을 수 있으므로 `work/private-youtube/`를 삭제할 수 있습니다.
분석 결과와 음원 해시를 24시간 동안 재사용해 같은 옵션으로 다시 열 때 다운로드를 생략합니다.
교정은 영상 ID와 음원 해시에 연결하며 원본 인식 결과와 별도로 보존합니다.
템포·박자·분석 옵션·엔진 환경을 변경하거나 캐시가 만료되면 음원을 다시 받아 분석할 수 있습니다.
음원을 보관하지 않으므로 이 경로의 결과는 원본 음원이 필요한 실제 곡 벤치마크에 바로 사용하지 못합니다.

### PO Token 공급기와 접근 검증

[bgutil-ytdlp-pot-provider](https://github.com/Brainicism/bgutil-ytdlp-pot-provider) 2.0.2의
Python 플러그인과 공급 서버를 같은 버전으로 고정합니다. 서버 소스 커밋은
`26475e9d3665b972c4aeb83b4dbaafcf64b88438`이며 GPL-3.0-only 원본은
저장소에서 제외한 `work/pot/provider-2.0.2/`에 설치합니다. 별도 유료 API·Docker는 사용하지 않습니다.
서버는 기존 Deno로 실행하고 로컬 `127.0.0.1:4416`에만 연결합니다. 브라우저에 이 포트를 공개하지 않습니다.
네트워크·CA 설정은 보존하며 토큰 원문을 앱 진단이나 실행 로그에 저장하지 않습니다.

로컬 수동 설치는 `python -m chordapp.service.pot install`을 실행하세요.
Codespaces의 설치·시작 스크립트는 이를 자동 처리합니다. `CHORDAPP_ENABLE_POT=1`이면
`mweb` 클라이언트와 HTTP 공급기를 사용합니다. 개인 모드·yt-dlp 설정도 모두 켜져야 적용됩니다.
비교용 `CHORDAPP_ENABLE_POT=0`에서는 외부 공급 플러그인을 끄고 기존 기본 클라이언트를 사용합니다.
서버 환경변수에서 이 값을 지정하면 Codespaces의 기본값보다 우선합니다.

**검색 설정 · 실행 상태**의 ‘토큰 공급기: 연결됨’은 서버와 플러그인의 연결·버전 확인입니다.
실제 토큰 생성이나 영상 다운로드 성공을 뜻하지 않습니다. 설치·시작 오류, 토큰 생성 실패,
HTTP 403을 구분해 확인해야 합니다. 설치 실패 로그는 `work/pot/install.log`에 남습니다.
실행 중인 공급기가 없으면 분석 요청이 다시 시작을 시도하고, 시작 실패는 명시적으로 안내합니다.

라이브·15분 초과 영상은 지원하지 않습니다. 토큰 공급으로 모든 HTTP 403이 해결되는 것은 아닙니다.
영상 권한·지역·로그인·서버 접속 제한과 네트워크 오류는 별도로 남을 수 있습니다.
[공식 PO Token 안내](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide)를 참고하세요.

실제 접근률은 동일 환경·동일 영상 목록에서 공급기 사용 전후로 비교합니다. 먼저 오류가 발생했던
`BzYnNdJhZQw`와 다른 채널·장르의 공개 음악 영상 4개 이상을 정해 영상 정보 조회, 토큰 공급,
음원 다운로드, 변환, 분석, 플레이어 동기화의 성공 여부를 각각 기록합니다.
캐시 적중은 새 다운로드 성공으로 계산하지 않습니다. 비교 실행은 별도 임시 데이터 폴더를 사용하거나
만료 후 수행하고 기존 교정을 지우지 않습니다. 제한된 영상과 미지원 영상도 분모에서 임의로 빼지 않고
전체 결과와 지원 범위 내 결과를 함께 보고합니다. 접근 성공률과 코드 인식 정확도는 별도 지표입니다.
현재 개발 환경의 실제 토큰 생성 요청은 외부 HTTP 403으로 실패했습니다. 로컬 서버 실행·플러그인
전달 검증만으로 Codespaces의 영상 접근 성공이나 ‘거의 모든 영상’ 지원을 주장할 수 없습니다.

이전 버전이 개인 PC에서 작동했다면 실행 환경과 다운로드 설정이 동시에 달라진 상태입니다.
**검색 설정 · 실행 상태 → 영상 연결 비교**는 위 영상 링크를 동일 서버에서 두 번 시험합니다.
기존 `android,ios,tv,web` 클라이언트 설정과 현재 설정을 비교하며, 현재 설정은 토큰 공급기
사용 여부도 그대로 반영합니다. 각 경로는 최대 90초 다운로드, 40MB·15분 제한과 WAV 검증을
거치고 임시 파일을 삭제합니다. 토큰 공급 서버 시작까지 포함해 최대 약 4분 동안 화면을 유지하세요.
서버 전체에서 비교 작업 하나만 허용하고, 분석·캐시·사용자 교정에는 기록하지 않습니다.
결과는 키·토큰·원문 로그·영상 URL 없이 메모리에 남아 같은 서버에서 새로고침으로 확인할 수 있으며
서버를 재시작하면 없어집니다. 상태 복사에도 비교 결과가 포함됩니다.

이 비교는 같은 yt-dlp 버전·재시도·파일 제한·설정 파일 무시 조건에서 클라이언트 구성을 비교합니다.
이전 PC의 OS·도구 버전·전역 설정이나 다운로드 캐시를 재현하지 않습니다. 기존 설정만 성공하면
클라이언트 구성의 회귀 증거가 됩니다. 두 설정이 모두 실패한 사실만으로 서버 IP 차단이라고
확정하지 말고, 같은 설치를 개인 네트워크에서 실행한 결과와 비교해야 합니다.

접근 범위를 넓히는 다음 판단은 실패 단계별 증거로 진행합니다.

| 관측 결과 | 다음 조치 | 한계·완료 기준 |
|---|---|---|
| 토큰 공급기 미설치·시작 실패 | 고정 의존성·네이티브 모듈·로컬 연결 수정 | 버전 일치와 실제 토큰 생성 확인을 구분 |
| 토큰 생성 성공 후에도 여러 공개 영상이 403 | 같은 영상·같은 버전을 사용해 Codespaces와 개인 네트워크의 실행 결과 비교 | 원인을 확인하기 전 서버 구매·프록시 서비스 도입 금지 |
| 개인 네트워크에서만 안정적으로 동작 | 개인 PC의 음원 공급 보조 서비스와 비공개 연결 설계 검토 | iPad 입력 흐름 유지, 상시 실행 장비·인증 필요; 아직 구현하지 않음 |
| 특정 영상만 제한·삭제·지역 차이 | 실패 사유 보존, 사용자가 다른 공개 버전을 선택하도록 지원 | 다른 편집본을 원래 영상과 같은 타임라인으로 취급하지 않음 |
| 다운로드 후 분석 지연·탭 종료 문제 | 서버 작업 큐·진행 상태·결과 재열람 구현 | 브라우저 종료와 서버 중지의 차이를 명확히 검증 |

별도 분석 카탈로그나 권한 음원 공급 API는 보조 경로로 검토하되 전체 YouTube 검색 결과를
대체한다고 가정하지 않습니다. 현재는 쿠키 수집, 유료 대리 서버, IP 순환, DRM 해제 기능을 추가하지 않습니다.
실제 영상 접근이 확인될 때까지 박자·코드 알고리즘 조정은 이 작업과 분리합니다.

### 별도 음원 연결

1. YouTube 탭에 영상 링크를 입력합니다. 검색을 쓰려면 `YOUTUBE_API_KEY`를 설정합니다.
2. 연결된 음원이 없다면 **사용 권한이 있는 음원 연결 · 변경**을 엽니다.
3. 직접 녹음했거나 권리자가 분석·보관을 허락한 별도 원본을 선택하고 권한 근거를 기록합니다.
4. 영상과 같은 녹음·편집본인지 확인하고 필요하면 시작 시차와 사용 기한을 지정합니다.
5. **연결하고 분석**을 누릅니다. 이후에는 같은 링크나 **연결한 음원 다시 열기**로 결과를 엽니다.

영상 시각 = 음원 시각 + 영상 시작 시차입니다. 음원 0초가 영상 5초에 해당하면 `5`를 입력합니다.
다른 편집본·라이브 버전·속도가 다른 영상은 동기화 지원 범위에 포함하지 않습니다.
동일 녹음 여부 확인을 하지 않은 연결은 보관할 수 있지만 영상 분석을 시작하지 않습니다.
영상과 무관한 분석은 **로컬 파일** 탭을 이용하세요.

연결할 수 있는 형식은 WAV·FLAC·MP3·OGG·AIFF이며 최대 40MB·15분입니다.
권한 확인 기록은 사용자 입력이며 앱이 권리를 자동으로 검증하거나 사용 허락을 부여하지 않습니다.
이번 버전에는 일반 상용 음원 공급 카탈로그가 없습니다.

YouTube Data API와 oEmbed는 영상 정보를, 공식 IFrame 플레이어는 영상 재생을 담당합니다.
선택적인 개인 자동 분석은 공식 Data API가 아닌 별도 공급 모듈이며, 공식 API의 오디오 제공 기능이 아닙니다.

- [YouTube 이용약관](https://www.youtube.com/t/terms)
- [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies)
- [Google 개인정보처리방침](https://policies.google.com/privacy)

영상 정보·플레이어·개인 자동 분석을 사용할 때 YouTube에 요청이 전송됩니다.
별도로 등록한 원본 음원은 이 서버에 보관하고 YouTube에 업로드하지 않습니다.
앱의 분석 결과는 YouTube가 제공한 정보가 아닙니다.

## 저장·교정·재열람

- `data/authorized_audio/`: 내용 해시로 보관한 원본. 별도 다운로드 API는 제공하지 않습니다.
- `data/audio_sources.sqlite3`: 영상 연결, 권한 근거·기한, 버전·시차.
- `data/cache.sqlite3`: 원본 분석과 별도 영상 메타데이터 캐시.
- `data/corrections.sqlite3`: 사용자 교정·템포·박자 지정.
- `work/private-youtube/`: 개인 자동 분석의 요청별 임시 파일. 요청 종료 시 삭제.

동일 음원·연결 버전·분석 옵션·설치 환경에서는 원본 분석을 재사용합니다.
실제 추적기나 소스 분리가 폴백한 결과는 선호 엔진의 정상 결과로 캐시하지 않습니다.
음원 연결을 교체하면 새 버전과 교정 키를 사용하며 기존 교정은 보존하지만 자동 적용하지 않습니다.
과거 `youtube:<id>` 캐시·교정도 삭제하지 않고 새 연결에 자동 승계하지 않습니다.
캐시 사용 여부와 원본 분석 출처는 별도 필드입니다.

코드 칸을 클릭해 교정하고 다시 열어도 원본 인식 결과는 덮어쓰지 않습니다.
연결 해제나 권한 만료는 캐시 조회도 차단합니다. 연결 해제는 파일 삭제가 아닙니다.
저장 데이터를 완전히 지우려면 서버를 멈추고 위 파일·디렉터리를 삭제하세요.
음원과 DB는 `data/` 아래에 두며 저장소에 커밋하지 않습니다.

YouTube 메타데이터는 분석과 분리해 24시간 뒤 갱신합니다. 제목으로 조회한 로컬 코드 DB는
`/api/lookup`에서 참고 진행으로 사용할 수 있지만 영상 동기화 분석을 대신하지 않습니다.

## API

| 경로 | 용도 |
|---|---|
| `GET /api/youtube/source?url=...` | 영상 정보·음원 연결 가능 상태 |
| `GET/POST /api/settings/youtube` | 키 등록 여부 / 개인 모드에서 연결 확인 후 키 저장 |
| `GET /api/diagnostics` | 키를 제외한 실행 버전·설정·최근 오류 |
| `POST /api/diagnostics/youtube-connection` | 개인 모드·같은 출처에서 실제 음원 연결 두 설정 비교 |
| `POST /api/audio-sources` | 음원과 권한·영상 연결 등록 (multipart) |
| `GET /api/audio-sources` | 연결한 음원 목록 |
| `DELETE /api/audio-sources/{video_id}` | 연결 사용 해제 |
| `POST /api/youtube` | 연결 음원 또는 개인 자동 분석·캐시 조회 |
| `POST /api/analyze` | 로컬 파일 분석 |
| `POST /api/corrections` | 원본과 별도로 교정 저장 |

연결이 없거나 기한 만료·해제·동일 녹음 미확인·파일 유실·내용 변경 시
`/api/youtube`는 HTTP 409와 `detail.code`, `detail.message`를 반환합니다.
API 문서는 실행 후 `/docs`에서 확인할 수 있습니다.
개인 공급 경로의 연결 실패·지원 불가·잘못된 음원은 HTTP 502, 시간 초과는 504,
필수 도구 누락은 503으로 안내하며 `detail.code`와 `detail.message`를 제공합니다.

## 검증과 알려진 한계

```bash
python -m pytest tests -q
python -m chordapp eval
python -m chordapp beateval
```

`beateval`의 기본값은 정답 박자를 입력하지 않는 자동 평가입니다. 이전 명령은 정답의
마디당 박 수를 미리 제공했으므로 이전 수치를 자동 박자 인식 성능과 직접 비교하면 안 됩니다.
기존 평가 디렉터리에 생성 기록이 없으면 처음 한 번 `--regenerate`가 필요합니다.
다음 두 조건을 같은 음원에서 비교할 수 있습니다.

```bash
python -m chordapp beateval --dir work/beat-baseline --regenerate --tracker librosa --json-out work/beat-auto.json
python -m chordapp beateval --dir work/beat-baseline --meter-mode reference --tracker librosa --json-out work/beat-reference.json
```

JSON에는 음원 해시·생성 조건·엔진 소스 해시·설치 버전·예측 시각을 기록합니다.
비트 F와 다운비트 F에 더해, 시작·끝 경계가 모두 맞는 마디 구간 F를 따로 계산합니다.
librosa 경로는 박자표 추정 대신 기본 4박을 사용하므로 자동 평가에도 이 한계가 반영됩니다.
기존 6/8 이름의 표본은 합성기 6펄스 기준이며 실제 겹박자 해석의 평가를 대신하지 않습니다.

후보 비교에는 `--tracker plp`, `--tracker beat-this-model`, `--tracker beat-this-legacy`를
사용합니다. beat_this는 별도 설치와 체크포인트가 필요하며 `--checkpoint`로 로컬 파일도 지정할 수 있습니다.
명시한 후보 실행이 실패하면 librosa의 점수를 그 후보 성능으로 보고하지 않고 중단합니다.
`beat-this-model`은 모델 이벤트를 보존하고, `beat-this-legacy`는 기존 전역 간격·고정 마디 보정을 재현합니다.
기본 엔진은 교체하지 않았습니다. PLP는 현재 16곡에서 더 낮았고 beat_this 실제 비교는
공식 모델 파일 다운로드 HTTP 500으로 실행하지 못했습니다. 모의 모델 시험을 실제 성능으로 해석하지 마세요.

사이트의 **바로 보기 — 데모 음원 → 인식 검증 음원**을 열면 추가 합성 7곡을
터치로 분석·재생하고 생성 시 정답과 비교할 수 있습니다. 기존 5곡과 별도 디렉터리에 생성합니다.
같은 근음의 화음 종류 변화, 한 박·두 박·세 박마다 바뀌는 코드, 전위 코드를 포함합니다.
현재 전위 표본에서는 근음·화음 종류 인식이 모두 실패하므로 이 버튼은 약점 확인용입니다.

코드 비교를 다시 실행하려면 같은 디렉터리를 두 번 평가합니다.

```bash
python -m chordapp eval --suite stress --dir work/chord-stress --tracker librosa --dataset-kind synthetic --json-out work/chords-current.json
python -m chordapp eval --suite stress --dir work/chord-stress --tracker librosa --dataset-kind synthetic --legacy-chords --json-out work/chords-legacy.json
```

JSON에는 음원·정답 해시, 실행 경로, 예측 구간, 화음 종류별 정확도, 전위 포함 일치율과
코드 경계 F(±100ms)를 담습니다. `seventh`는 호환을 위해 유지한 이름이며 실제로는 내부 화음 종류
전체를 비교합니다. 표준 MIREX seventh 축약 규칙과 다릅니다. 무주석 구간을 무화음 정답으로
계산하지 않으며, 파싱에 실패한 정답 코드나 판정 불가 `X`는 오류로 안내합니다.
파서가 축약하는 확장음 표기는 현재 내부 어휘 기준이며 모든 알터드 음을 평가하지는 못합니다.
20ms 프레임 샘플 기반 평가이므로 매우 짧은 구간의 시간 가중에는 근사 오차가 있습니다.
외부 음원은 기본적으로 `unverified`이며 사용자 전체 검수 없는 실제 곡을 공식 평가로 표시하지 않습니다.

테스트는 외부 YouTube 요청 없이 공급·권한·캐시·교정·API 동작을 검증합니다.
합성 평가 5곡·16곡의 수치는 실제 음악 정확도의 증거가 아닙니다.
이번 코드 변경으로 기존 5곡 화음 종류 정확도는 98.8%→97.7%, 추가 7곡은 28.3%→71.1%였습니다.
모두 길이 가중 평균이며, 한 박 코드 보존의 이득과 일부 화음 종류 오탐 증가를 함께 기록합니다.

템플릿·근음 추론과 기본 박자 엔진은 유지했습니다. 계층형 인식기는 같은 근음 안에서도 화음 종류를
바꾸며, 코드 길이만으로 한 박 코드를 지우거나 경계를 마디로 옮기는 처리는 기본값에서 제외했습니다.
기존 처리는 비교용 `--legacy-chords`로 보존했습니다. 분석 버전은 6으로 올라 기존 캐시는
새 결과로 다시 계산하며 사용자 교정은 별도로 유지합니다.
추적기가 판단한 마디당 박 수를 구간 번호·결과·차트까지 보존하며, 수동 박자 지정이 자동 추정보다 우선합니다.
자동으로 되돌리면 추적기의 박자를 다시 사용하고, 추정이 불가능한 경로에서는 기본 4박을 사용합니다.
전체 곡 단일 조성·고정 박자 구조, 알터드 코드 인식 범위는 후속 과제입니다.
기존 `benchmark`는 새 예측에 교정을 얹어 정답을 구성하는 한계가 있으므로
엔진 우열을 주장하는 공식 실제 곡 평가에 사용하지 마세요. 독립 정답 스냅샷이 먼저 필요합니다.

긴 분석은 현재 동기 요청입니다. 작업 큐·중복 실행 방지·취소·진행 상태는 다음 단계입니다.
실제 권한 음원과 동일 버전 영상의 동기화, iPad Safari는 해당 자료와 기기에서 별도 검증해야 합니다.
외부 유료 API나 GPU 서비스는 사용하지 않습니다.

브라우저 검증은 Playwright가 있는 Node 환경에서 실행합니다. 테스트 서버는 임시 DB와 가짜

## iPad·휴대폰에서 Codespaces로 검증

`.devcontainer/devcontainer.json`과 `scripts/`에 Python 3.12 CPU 환경의 자동 설치·실행 구성이 있습니다.
GitHub에 이 변경이 반영된 브랜치에서 다음 순서로 시작합니다.

1. 저장소의 **Code → Codespaces → Create codespace**에서 2코어 환경을 선택합니다.
2. 최초 의존성 설치가 끝나면 앱이 자동 실행됩니다. 이미 만든 Codespace는 컨테이너를 재빌드해야 설정이 적용됩니다.
3. **Ports → 8000 → Open in Browser**를 엽니다. 포트 공개 범위는 **Private**로 유지합니다.
4. 같은 GitHub 계정으로 로그인한 iPad·휴대폰에서 그 HTTPS 주소를 엽니다.
5. 합성 데모로 화면·터치 교정을 확인한 뒤, 개인 링크 분석 또는 별도 원본 음원 연결을 검증합니다.
6. 검증을 마치면 GitHub의 Codespaces 목록에서 **Stop codespace**로 실행을 중지합니다.

시작 스크립트는 Codespaces에서 `gh codespace ports visibility 8000:private`를 실행하고,
비공개 설정에 실패하면 새 서버를 시작하지 않습니다. 서버 로그는 `work/dev-server.log`에 저장합니다.
자동 실행에 실패하면 터미널에서 `bash scripts/setup-dev.sh`와 `bash scripts/start-dev.sh`를 순서대로 실행하세요.
기존 서버가 있으면 중복 실행하지 않습니다.

Codespaces의 포함 사용량은 GitHub 요금제에 따라 다르고 실행 시간·저장 공간에 비용이 붙을 수 있습니다.
유휴 중지 시간을 짧게 설정하고 유료 초과 사용은 예산 설정으로 제한하세요. Codespace를 삭제하면
커밋하지 않은 음원·DB도 없어지므로, 삭제 전 필요한 데이터를 개인 보관소에 백업해야 합니다.

- [비공개 포트 미리보기](https://docs.github.com/en/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace)
- [Codespaces 사용량·비용](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces)

화면은 320px·390px 휴대폰과 834px 태블릿 너비에서 터치 편집·재열람을 검증합니다.
터치 환경에서는 코드 칸을 누르면 저장·취소 버튼이 있는 편집창이 열립니다.
실제 iPad Safari와 실제 YouTube 영상 동기화 검증은 별도로 필요합니다.

## 정식 웹사이트·앱으로 운영할 때

현재 개인용 웹앱을 개발·검증한 뒤 다음 환경을 준비합니다. 이번 단계에서 유료 서버를 개설하지 않습니다.

| 구성 | 개인용 초기 운영 | 확대 시 검토 |
|---|---|---|
| 실행 서버 | Linux CPU 서버 하나에서 FastAPI·화면 제공 | 분석 작업자 분리, 동시 처리 수 제한 |
| 외부 접속 | HTTPS 주소, 도메인 또는 관리형 주소 | TLS 갱신·접속 장애 모니터링 |
| 접근 제어 | 본인 로그인, 요청·파일 접근 제한 | 사용자별 데이터·교정 격리 |
| 분석 작업 | 작업 큐, 진행·실패 상태, 시간 제한 | 재시도·취소·작업 재개 |
| 분석 기록 | 영구 디스크의 SQLite와 정기 백업 | 필요해질 때 PostgreSQL 등으로 이전 |
| 음원 보관 | 비공개 영구 저장소, 삭제·기한 관리 | 오브젝트 저장소, 용량·사용자별 한도 |
| 음원 공급 | 허용된 원본과 정확한 영상 버전의 연결 | 권리자·공급 API와의 명시적 이용 조건 |
| 검증·운영 | 고정 의존성, 회귀 테스트, 오류 기록 | 독립 정답 평가·배포 자동화 |
| 앱 형태 | 태블릿·모바일 반응형 웹 | PWA 설치, 필요할 때 네이티브 앱 |

맥미니 등 개인 컴퓨터도 상시 서버로 사용할 수 있습니다. 외부 접속용 네트워크와 HTTPS·인증,
전원·인터넷 유지, 업데이트·백업을 직접 관리해야 합니다. 원격 분석이라면 iPad의 연산 성능과는
무관하게 서버 CPU와 메모리가 분석 속도를 결정합니다. 구매 전 실제 곡의 CPU 시간·메모리를 측정하고
작은 클라우드 서버의 장기 비용과 비교하는 것이 좋습니다. 현재는 GPU나 새 컴퓨터가 필수 조건이 아닙니다.

박자 전달 회귀 검증에서는 추적 결과를 통제해 3박·4박·6박의 결과·차트와 수동 지정 우선순위를 확인합니다.
모델 자체의 박자 인식 정확도를 측정하는 테스트는 아닙니다. 브라우저에서도 확인하려면 검증 서버에
`CHORDAPP_TEST_METER=3`, 브라우저 스크립트에 `CHORDAPP_EXPECTED_METER=3`을 지정하세요.
박자 처리 수정으로 이전 버전의 분석 캐시는 한 번 재계산될 수 있으며, 저장된 교정은 별도로 유지됩니다.
