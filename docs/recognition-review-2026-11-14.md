## 박자 추적기

librosa 경로는 기본 4박을 사용한다. 다운비트는 저역 온셋·백비트 같은 휴리스틱으로
위상을 고른다. 기본 코드의 두 표본에서 3박을 마디 첫 박으로 잡는 문제는 남아 있다.
임계값을 조정해 박자표 추정이나 범용 다운비트 인식이 생긴다고 판단하지 않았다.

기존 beat_this 연결부는 전체 곡의 중앙 비트 간격으로 비트를 삭제·보충한 뒤
일정한 마디 격자로 다시 배치한다. 정상적인 템포 변화나 변박도 오류로 처리할 수 있다.
이 경로를 `legacy`로 보존하고 이벤트를 바꾸지 않는 `model` 비교 모드를 추가했다.
모델은 비트와 다운비트 시각을 제공하며 박자표를 직접 제공하지 않는다. 새 모드는
여러 다운비트 사이의 비트 수가 모두 같을 때만 마디당 박 수를 추론하고, 다르면 미정으로 둔다.
현재 앱의 전체 곡 고정 마디 구조가 변박을 표현하는 문제까지 해결한 것은 아니다.

| 동일 16곡, 정답 박자 미입력 | 비트 F | 다운비트 F | 마디 구간 F | 템포 배수 오류 |
|---|---:|---:|---:|---:|
| librosa 변경 전 | 98.2% | 72.9% | 68.8% | 0/16 |
| librosa 변경 후 | 98.2% | 72.9% | 68.8% | 0/16 |
| librosa PLP 기본 설정 후보 | 71.5% | 58.3% | 22.2% | 5/16 |

곡별 평균, ±70ms다. PLP는 펄스만 제공하므로 다운비트는 같은 기존 후속 추정기를 쓴다.
모든 음원 해시를 비교했고 librosa의 전후 비트 시각도 동일했다. 이 결과로 PLP를
기본 엔진으로 바꾸지 않았다. 템포 변화에 대한 일반적 우열을 이 세트로 판단하지 않는다.

beat_this v1.1.0의 공식 구현과 CPU 실행 조건을 검토했다.
[공식 코드](https://github.com/CPJKU/beat_this)의 `final0` 체크포인트는 공식 DAV 경로와
공식 공유 폴더 다운로드 경로 모두 HTTP 500이었다. torch·beat_this를 새로 설치하거나
실제 모델 추론을 실행하지 않았다. 후보의 성능이나 소요 시간은 검증하지 못했다.
출력 보존·변박·2/3/4/6/7박 시험은 모의 모델을 사용한 어댑터 계약 시험이다.

확인해 수정한 동작은 다음과 같다.

- 증가하지 않거나 NaN·음수인 시각, 유효하지 않은 템포를 검증하고 실패 시 이유를 표시한다.
- 선택 모델이 실패해 librosa로 진행한 사실을 실행 정보·경고에 남긴다. 예외 원문의 URL·경로는 노출하지 않는다.
- `max_seconds`보다 뒤의 모델 비트·다운비트를 잘라 코드 구간이 분석 범위 밖으로 나가지 않게 한다.
- 마디 이동으로 범위 밖에 나간 다운비트를 끝 비트에 강제로 붙이지 않고 제외한다.
- 기본 4박 표시와 실제 자동 박자 판단을 구분한다. 후보 비교 중 폴백하면 후보 점수로 계산하지 않는다.

## 코드 인식

근음 추론·템플릿 점수·기존 임계값은 유지했다. 수정 전 추가 합성 7곡의 WAV와
생성 시 정답을 먼저 고정했다. 정답은 인식 결과나 사용자 교정에서 만들지 않았다.
다만 기존 데모와 같은 합성기를 사용하므로 독립적인 악기·녹음 조건 검증은 아니다.

원인은 두 가지였다. 계층형 인식기는 근음이 같은 전체 구간을 한 번에 모아 화음 종류를
정했기 때문에 `C → C7 → Cmaj7 → C6`를 한 종류로 만들었다. 또한 추가 평활화는
두 박보다 짧은 코드를 삭제하고 마디 스냅은 근거 없이 경계를 옮겼다.

새 방식은 같은 근음 안에서도 박별 화음 종류 변화를 찾고 같은 종류가 연속한 구간만
묶어 판정한다. 기존 인식기의 시간 방향 추론은 유지하면서 추가 길이 삭제·마디 스냅은
기본값에서 제외했다. 기존 동작은 `--legacy-chords`로 재현한다.

| 동일 음원, 화음 종류 일치율 | 기존 | 변경 후 |
|---|---:|---:|
| 같은 근음의 장화음 변화 | 25.0% | 96.1% |
| 같은 근음의 단화음 변화 | 25.0% | 95.6% |
| 두 박마다 화음 종류 변화 | 24.9% | 91.4% |
| 같은 근음의 sus 변화 | 25.0% | 90.4% |
| 세 박마다 코드 변화 | 87.6% | 98.4% |
| 한 박마다 코드 변화 | 17.7% | 93.8% |
| 전위 코드 | 0.0% | 0.0% |
| 추가 7곡, 길이 가중 평균 | 28.3% | 71.1% |
| 기존 데모 5곡, 길이 가중 평균 | 98.8% | 97.7% |

한 박 코드 표본의 근음 정확도는 23.7%→93.8%다. 기존 5곡의 근음·3화음은
98.8%를 유지했지만 화음 종류 오탐이 늘었다. 특히 `ballad_sevenths`는 99.3%→95.0%,
경계 F는 100%→84.6%다. 세밀한 변화 보존과 오탐 증가의 상충을 숨기지 않는다.
추가 보정을 쌓아 이 합성 발라드 하나에 맞추지 않았다.

전위 표본은 정답 `C/E`를 `Em`처럼 베이스 쪽 근음으로 읽었다. 합성기 보이싱이
정답 근음의 상성부와 지정 베이스를 실제로 생성하는 것을 확인했다. 근음·베이스를
별도로 추론하는 구조가 다음 검토 대상이며 베이스 가중치 한 개를 조정해 해결했다고 주장하지 않는다.
틀린 코드에도 내부 확신도가 높아 정답 확률처럼 사용할 수 없다. 화면에 이를 명시했다.

평가에는 화음 종류별 일치율, 전위 포함 일치율, 코드 경계 F(±100ms)를 추가했다.
근음만 같은 오답·전위 오류·경계 오류를 구분한다. 무주석 구간은 채점에서 제외하고,
예측 누락은 무화음 정답으로 계산하지 않는다. `X`와 파싱 오류도 무화음으로 바꾸지 않는다.
호환 이름 `seventh`는 내부 종류 전체 비교이며 표준 MIREX 축약 규칙과 다르다.
기존 파서는 일부 추가음 표기를 축약하므로 모든 알터드 음을 평가하는 지표는 아니다.
