# 음원 확보 실패 조사 — 2026-11-11

## 완료 기준과 현재 상태

완료 기준은 실제 영상의 음원을 확보하고 유효한 WAV로 변환·검증하는 것이다.
검색 성공, 공급기 `/ping` 성공, 합성·모의 테스트 통과를 완료로 간주하지 않는다.
현재 실제 영상 확보 문제는 **미해결**이다.

사용자 Codespaces의 동일 영상 비교 결과:

| 설정 | 시간 | 결과 | 단계 |
|---|---:|---|---|
| 기존 android,ios,tv,web | 2.4초 | HTTP 403 | 영상 정보 조회 |
| 현재 mweb + 공급기 | 1.7초 | 자동화 확인 요구 | 영상 정보 조회 |

공급 서버와 플러그인 2.0.2는 연결됐다. 실제 토큰 생성 성공은 확인하지 못했다.
이전 정상 사이트의 서버 위치는 확인할 수 없으며, iPad로 접속했다는 사실만으로 실행 위치를 추정하지 않는다.
Codex 환경의 앞선 실제 토큰 생성 시도도 공급기 HTTP 500/외부 HTTP 403으로 실패했다.
이 환경의 명시적인 프록시 거부는 다른 경로나 프록시 해제로 재시도하지 않는다.

## 근거와 판단

- [yt-dlp 공식 알려진 문제](https://github.com/yt-dlp/yt-dlp/issues/3766): 로그아웃 상태의 IP가 이미 차단된 경우 PO 공급기를 추가해도 도움이 되지 않을 수 있다고 설명한다.
- [공식 PO Token 안내](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide): mweb + 공급기는 권고 구성이지만 모든 접속 제한의 해결책은 아니다.
- [최근 403 보고 #17989](https://github.com/yt-dlp/yt-dlp/issues/17989): 2026-11-06 이후 댓글의 web_embedded 실험은 주로 형식 URL·다운로드 단계 사례다. 현재 mweb의 메타데이터 단계 자동화 확인과 같은 원인으로 단정할 수 없다.
- 2026-11-11 확인 기준 안정판 2026.10.26과 공급기 2.0.2는 최신 릴리스다. 근거 없이 버전을 바꾸거나 클라이언트를 계속 추가하지 않는다.

개별 서버 IP 제한은 유력한 가설이지만 동일 설치의 다른 실행 환경에서 비교하기 전 확정하지 않는다.
이미 시도한 세 차례 이상 수정 이후에는 임시 보정을 누적하지 않고, 독립 실행 환경에서 먼저 실제 확보 여부를 검증한다.

## 독립 최소 재현

`scripts/probe_youtube_audio.py`는 프로젝트의 분석기·FastAPI·DB·.env를 로드하지 않는다.
`requirements-source-probe.txt`는 개인 설치와 같은 yt-dlp·EJS·Deno·FFmpeg 패키지 네 개만 고정한다.
계정·API 키·쿠키·PO 공급 서버·외부 프록시 서비스 없이 표준 설정을 먼저 시험한다.
표준 설정이 실패하면 공식 FAQ의 IPv4 지정만 한 번 비교한다. 환경 프록시가 명시적으로 거부하면 중단한다.
두 설정은 메모리에 캡처한 출력에서 고정 오류 분류·HTTP 상태·단계만 기록하고 원문은 보관하지 않는다.

- 각 설정 시간 제한 90초, 재시도 0회, 15분·40MB 제한.
- 유효한 mono/22050Hz WAV가 실제로 만들어져야 성공이다.
- 성공·실패·시간 초과 후 임시 파일을 삭제한다. 분석·캐시·교정은 읽거나 쓰지 않는다.
- 성공하면 나머지 시험을 생략한다. 명시적인 프록시 거부 후에도 추가 요청하지 않는다.
- 시작 시 최대 두 설정만 수행한다. 웹 요청으로 새로운 URL을 지정하거나 재실행할 수 없다.
- 공개 페이지는 요약 기록만 제공하며 음원·파일·키 조회 경로가 없다.
- 서비스 재시작 시 시험도 다시 실행되므로 결과 확인 후 임시 서비스를 삭제한다.

```bash
# 네트워크 요청 없이 설치·도구 실행만 확인
python scripts/probe_youtube_audio.py selfcheck
# 허용된 환경에서 한 곡을 실제 검증
python scripts/probe_youtube_audio.py run
```

## 별도 무료 환경의 검증 후보 — 아직 배포하지 않음

`render.yaml`은 최종 사이트가 아닌 음원 확보만 수행하는 임시 서비스다.
Render Free 1개, Python 3.12.14, 자동 배포 꺼짐, DB·유료 디스크·API·도메인 없이 구성했다.
사용자는 본인 Render 계정으로 배포 설정을 검토하고 생성해야 한다. 새 서비스 사용 승인과 계정 로그인이 필요하다.
실제 배포·Render에서의 음원 다운로드는 아직 검증하지 않았다. 메모리 한도 등으로 실행 자체가 실패할 수도 있다.

[배포 설정 검토 링크](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fdr2mer05%2Fchord-recognition%2Ftree%2Ffeat%2Fauthorized-audio-sources)

표시되는 계획이 Free인지 확인하고 유료 전환은 하지 않는다. 테스트가 완료되면 배포 주소의 결과를 확인한다.
성공하더라도 한 곡의 결과로 범용 지원을 주장하지 않는다. 다른 채널·장르 5곡 이상으로 확대하고,
그 결과가 확보되기 전에는 기존 사이트를 이전하거나 새 장비를 구매하지 않는다.
다른 환경에서 이 프로그램이 성공하면 현재 Codespaces에서도 같은 프로그램을 실행해 비교한다.
현재 앱의 mweb 결과와 다른 환경의 표준 클라이언트 결과만 비교해 서버 IP를 원인으로 확정하지 않는다.
실패하면 HTTP 상태·단계를 보존하고 이 호스팅 후보를 탈락시킨다. 같은 설정으로 반복 배포하지 않는다.

[Python 버전 지정](https://render.com/docs/python-version).
